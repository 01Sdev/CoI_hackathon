# 코디 스캔 UI 추출과 기능 연결 설명

사용자가 `design.html`에서 확정한 코디 입력창·오른쪽 폰 형태 대화창을 React 18·TypeScript로 옮겼다. 이번 변경은 UI와 호출 콜백까지다. 실제 제스처의 종류, 사람 판정 방식, 음성 인식 서비스와 분석·검색 방식을 새로 정하지 않는다.

## 사용자가 지정한 기능 흐름

아래는 기능을 연결할 때 따라야 하는 동작 설명이다. 연결 완료를 뜻하지 않는다.

| 사용자 행동 | 열리는 화면·동작 | 이번 변경에서 확인할 수 있는 것 |
| --- | --- | --- |
| 제스처 실행 | 질문 입력창 활성화 | 현재 ‘질문하기’ 버튼. `openRequest`를 증가시키면 같은 창이 열린다 |
| 대상 지정 | 지정한 사람에 대해 질문, 마이크 활성화 | 위치 선택 콜백. 실제 사람 판정과 마이크 시작은 연결 예정 |
| 말로 질문하거나 입력 후 전송 | 시야 안 오른쪽에 대화창을 열고 질문·답변 표시 | 입력·전송·폰 창 표시. 개발 페이지의 답변은 고정 UI 예시 |
| 옷 종류 질문 | 지정한 사람의 옷 설명 | 실제 분석 연결 예정 |
| 스타일 질문 | 지정한 사람의 스타일 설명 | 실제 분석 연결 예정 |
| 브랜드 질문 | 해당 옷의 브랜드 검색 | 검색 연결 예정. 확인되지 않은 브랜드를 표시하지 않음 |
| 이전 대화 | 기존 대화창 열기 | 구현됨 |
| 다시 지정 | 대상 선택으로 돌아가기 | 구현됨. 이미지·대상 번호·설명 없이 버튼만 표시 |
| 마이크 아이콘 | 음성 입력 다시 시작. 듣는 중이면 마치기 | 아이콘·상태·클릭 콜백. 실제 녹음은 연결 예정 |
| 대화창 × | 대화창을 접고 한 줄 입력창으로 돌아가기 | 구현됨 |
| 폰 상단의 빈 곳 드래그 | 시야 안에서 폰 창 이동 | 양쪽 곡선 모서리·스피커·제목 주변 포함. 테마·닫기 버튼은 클릭 유지 |
| 폰 오른쪽 아래 모서리 드래그 | 폰 크기 조절 | 구현됨. 방향키도 지원하며 −/+ 버튼은 없음 |

대상 지정·변경·해제·선택 취소·창 닫기 때문에 작성 중인 질문을 지우지 않는다. 실제 전송 시에만 입력을 비운다. 폰 창과 입력창은 부모 시야 영역 안에서 표시한다. 문구 ‘지정한 사람의 옷에 대해 물어보세요’를 유지한다.

## 파일·미리보기

- `src/ui/OutfitAssistant.tsx`: 재사용하는 UI와 타입·콜백. 원본 이미지나 카메라·마이크를 직접 읽지 않는다.
- `src/ui/outfit-assistant.css`: 승인된 중립색 다크·라이트 스타일. 기존 Pretendard 패키지를 재사용하며 스타일은 `fm-outfit`에 한정한다.
- `dev/outfit-assistant.html`, `dev/outfit-assistant.tsx`: 원본 카페 사진·모델·외부 API 없이 조작하는 개발 페이지. 사람 도형도 표시용이며 클릭 지점에 사람이 있다는 판정을 하지 않는다.

프로젝트에서 `npm run dev`를 실행한 뒤 `/dev/outfit-assistant.html`을 연다. 개발 페이지는 현재 프로덕션 빌드 입력에 포함되지 않는다. 기존 `MainScreen`·`Hud`·플러그인 호스트에는 자동으로 연결하지 않는다.

## 호출 측 연결 위치

`OutfitAssistant`의 부모는 `position: relative`와 크기가 있어야 한다. `target`, `draft`, `messages`, `voice`를 호출 측에서 관리하고 아래 콜백을 연결한다.

- `openRequest`: 제스처를 받는 코드에서 값을 증가시키면 입력창이 열린다. 실제 제스처는 이 PR에서 인식하지 않는다.
- `onTargetPick(point)`: 부모 시야 기준 0~1 지점. 실제 런타임에서 대상을 확인한 뒤 `target`을 갱신하고 음성 입력을 활성화하는 연결 위치다. `selectionKey`는 선택 변경을 구분하는 값이며 인물 ID·추적 ID가 아니다.
- `onDraftChange(text)`: 타이핑과 음성 변환 결과를 같은 입력 값에 반영한다. 대상이 해제돼도 값을 보존한다.
- `onMicToggle`, `onCancelVoice`: 실제 음성 시작·마치기·중단을 연결한다. 콜백이 없으면 마이크 버튼은 비활성이다. 실제 브라우저·글래스 지원과 권한을 확인한 뒤 연결해야 한다.
- `onSubmit(question, target)`: 질문과 현재 선택 정보를 전달한다. 대상이 없으면 전송하지 않고 선택 화면을 연다.
- `messages`: 확인된 결과를 전달하면 표시한다. 문자열은 React 텍스트 노드로 렌더링한다. 개발 페이지의 고정 답변 함수는 제품 컴포넌트에 포함되지 않는다.

후속 연결 시에는 기존 `02-SSRD.md` 경계를 따른다. 원본 판정·가림은 A, 플러그인·서버 호출은 B, UI는 C 소유다. 현재 SDK는 이미지 `delivery`와 200자 결과 한 줄만 지원하며, 질문·대화 계약은 별도 연결 작업이다. 실제 음성 연결 시에는 SRS C-8의 기존 ‘런타임 마이크 미사용’ 전제도 함께 정리한다. 이번 UI 추출은 core·가림 규칙·SDK·기존 요구사항을 바꾸지 않는다.

## 검증 범위

관련 근거는 사용자 요청에 따른 코디 UI 추출이며 기존 F8(HUD), F24(전송 범위), G1·G2(원본·범위 최소화)의 경계를 유지한다. 코디·제스처·대화는 기존 명세의 구현 완료 기능으로 기재하지 않는다.

타입 검사, 기존 UI assertion, 프로덕션 빌드와 개발 페이지에서 호출·선택·전송·다시 지정·초안 유지·다크/라이트·상단 드래그·크기 조절을 검증한다. 실제 제스처, 마이크 음성 인식, 실카메라·모델, 옷 분석, 브랜드 검색, 글래스 기기는 이 변경의 검증 범위에 들어 있지 않다. 직접 실행한 결과는 PR 본문에 기록한다.

## 앱 연결(2026-11-01, `track-c/outfit-ui`)

사용자 지시(2026-11-01): 배포 웹은 글래스가 없어 휴대폰 브라우저로 글래스 시야를 그대로 시연하는 화면이다. 휴대폰 안에 폰 모양 창을 또 그리면 앱처럼 보이므로, 앱에는 `OutfitAssistant`를 그대로 붙이지 않고 `src/ui/OutfitTalk.tsx`가 글래스 HUD 패널로 그린다. 이 컴포넌트와 개발 페이지는 시안 참고용으로 남긴다.

- 말풍선은 이 파일의 `.fm-outfit-message` 모양을 쓰고, 겉 글로우·테두리는 사용자가 준 zip 값(`outfit-talk.css`)이다. 폰 장식(스피커·홈 바·끌기·크기 조절)은 없다.
- 흐름은 `docs/designs/outfit-pipelines.md`를 따른다. 응시 칩(`GazeChip`) → 동의 → 시야 아래 말 막대(음성 받아쓰기, 탭·Enter·Space로 `askPlugin`) → 시야 오른쪽 가장자리 질문·답 패널(`outfitTurns`).
- `outfit-assistant.css`의 Pretendard `@import`는 지웠다. 앱은 `theme.css`가, 이 개발 페이지는 `dev/outfit-assistant.tsx`가 불러온다.

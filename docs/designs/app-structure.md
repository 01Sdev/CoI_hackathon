# 설계: 휴대폰 앱 구조와 시각 데이터 규약 화면

상태: 초안, 사용자 승인 대기 · 2026-11-01
- **근거:** PRD F8·F12·F22·F24·F25, 03-SRS FR-030·058·064, 02-SSRD "매니페스트 형식", `docs/designs/design-system.md`
- **시각 규칙 참고:** [elayadesign/ai-design-skills](https://github.com/elayadesign/ai-design-skills) `skills/landing-page-design` Part B(Visual System). 이 저장소에는 앱 화면 전용 스킬이 없어 앱에 맞는 규칙만 가져왔다(2.5).
- **시안:** 휴대폰 화면 여섯 장(S1~S6, 390×844)을 디자인 캔버스 "framelet 앱 화면 설계"(https://claude.ai/artifact/U47BvhrRCTHkraU7Aq5M9S)에 두었다. 화면끼리 링크로 이어져 있어 탭과 버튼을 눌러 흐름을 따라갈 수 있다. 시연 영상은 이 문서와 시안을 바탕으로 Claude Design에서 만든다.

## 1. 풀려는 문제

사용자 시연(2026-11-01)과 지금 휴대폰 화면에서 문제 세 가지가 보였다.

1. **플랫폼과 칼로리 앱이 한 몸처럼 보인다.**
   - 칼로리 앱의 결과("피자 약 285kcal · 고정표")가 플랫폼의 보호 카운터 바로 아래에, 같은 모양의 알약으로 붙어 있다.
   - 위쪽 알림 "칼로리에 사진 1장 전달"도 플랫폼 문구와 앱 이름이 한 줄에 섞여 있다.
   - 그래서 framelet이 직접 칼로리를 계산하는 것처럼 보인다.
2. **앱에 시각 데이터를 넘기는 약속(규약)이 화면에 없다.**
   - 매니페스트(`scenes`·`region`·`maxSide`·`maxPerMinute`·`network`)와 플랫폼 보장(원본 비유출, 얼굴 가림)은 코드에 있다.
   - 하지만 착용자가 "이 앱에 무엇을 넘기기로 했는지"를 앱을 켜기 전에 보고 동의하는 화면이 없다.
   - 지금은 아래쪽 시트의 앱 관리에 켜기 스위치만 있다.
3. **기록이 한 시트에 몰려 있다.** 연결된 앱 목록, 앱별 로그, 전체 로그가 카메라 화면 위 아래쪽 시트의 탭 네 개(전달 일시 정지·사용 기록·앱 관리·확인 화면)에 섞여 있다.

## 2. 결정

### 2.1 두 주체를 화면에서 나눈다

원칙은 이것이다. **framelet은 문틀이고, 앱은 문틀을 통해 조각을 받아 가는 손님이다.** 화면의 모든 요소는 둘 중 한쪽에 속하고, 모양으로 구별된다.

| | 플랫폼(framelet) | 앱(플러그인) |
| --- | --- | --- |
| 무엇을 보여 주나 | 카메라, 흰 전송 범위 틀, 보호 상태(앱에 반영된 사람 수), 전달 신호, 규약, 기록, 일시 정지 | 앱이 돌려준 결과(예: 칼로리 한 줄)와 앱의 상태 |
| 모양 | 어두운 바탕의 패널·알약. 색은 의미 색 세 가지(초록 보호, 주황 노출, 빨강 차단)의 점으로만 쓴다 | **앱 카드** 하나. 머리줄(앱 아이콘 글자·이름·"앱이 보낸 결과" 꼬리표)은 플랫폼이 어두운 칸에 그리고, 앱 문자열은 그 아래 **밝은 카드** 안에만 들어간다. 의미 색을 쓰지 않는다 |
| 위치 | 화면 위·가운데·아래 시트 | 홈 화면 아래쪽 "앱 결과" 칸에 앱마다 한 장씩 쌓인다. 보호 카운터 옆에 붙지 않는다 |
| 문구 주어 | framelet("framelet이 칼로리 앱에 사진 1장을 보냈습니다") | 앱("칼로리 앱 · 피자 약 285kcal") |

- **전달 신호는 방향을 보여 준다.** 위쪽 알림의 첫 줄을 "framelet → 칼로리", 둘째 줄을 "사진 1장 · 3.9KB · 얼굴 1개 가림 · 방금"으로 바꾼다. 화살표 왼쪽은 플랫폼, 오른쪽은 앱이다.
- **앱이 보낸 문자열은 지금처럼 `textContent`로만 넣는다.** 앱 카드의 바깥 틀(아이콘, 이름, 꼬리표)은 플랫폼이 그리고, 안쪽 한 줄만 앱 몫이다. 앱이 플랫폼 모양을 흉내 내 보호 표시처럼 보일 수 없게 하기 위해서다.
- **앱 아이콘과 이름은 플랫폼이 관리한다.** 이번 데모는 플러그인 시드(`core/plugins.ts`)에 아이콘 글자 하나와 강조색 하나를 둔다. 강조색은 의미 색(초록·주황·빨강)과 겹치지 않게 고른다.

### 2.2 시각 데이터 규약 화면(앱 연결 요청)

앱을 처음 켤 때와 앱의 매니페스트가 바뀐 뒤 처음 켤 때 이 화면을 띄운다. 착용자가 **허용**을 눌러야 앱이 켜진다. 휴대폰 권한 요청 창과 같은 자리이지만, 무엇을 얼마나 넘기는지를 항목으로 보여 준다.

화면은 위에서 아래로 세 덩어리다.

1. **앱 신원:** 아이콘 글자, 이름, 목적(`purpose`, 40자). 예: "칼로리 · 음식 칼로리 추정". 매니페스트에 만든 곳 항목이 없어 이번에는 넣지 않는다.
2. **framelet이 늘 지키는 것(앱이 바꿀 수 없음, 자물쇠 표시)**
   - 원본 화면은 보내지 않아요
   - 사람 얼굴은 가리고, 못 가리면 보내지 않아요
   - 흰 틀 밖은 보내지 않아요
   - 보낸 것은 모두 기록에 남겨요
3. **이 앱이 받는 것: 앱이 요청 → framelet이 허용(두 칸, F12와 같은 구조).** 아래 화면 문구는 칼로리 시드 매니페스트 값이다.

   | 항목 | 요청(매니페스트) | 허용 | 화면 문구(요청 / 허용) |
   | --- | --- | --- | --- |
   | 장면 | `scenes` | 선언한 장면만 | "음식" / "음식 앞에 있을 때만" |
   | 영역 | `region: target` | 대상 + 10%, 흰 틀 안 | "대상 하나" / "흰 틀 안의 대상 하나" |
   | 크기 | `maxSide` | 그 값 이하 | "긴 변 256px" / "긴 변 256px까지" |
   | 빈도 | `maxPerMinute` | 그 값 이하 | "분당 6장" / "10초에 1장까지" |
   | 받는 곳 | `network` | `network` ∩ 호스트 허용 목록 | "framelet 서버" / "framelet 서버만". `network: []`이면 "밖으로 안 보냄" |

- 버튼은 **거절**과 **허용하고 연결** 두 개다. 거절하면 앱은 꺼진 채로 남는다.
- 버튼 위에 고정 문구를 둔다. "앱이 조건을 바꾸면 다시 물어봐요. 연결은 앱 화면에서 언제든 끊을 수 있어요. 이미 보낸 사진은 되돌릴 수 없어요."
- 매니페스트가 바뀌면(`manifest.version` +1) 다음에 켤 때 다시 묻는다. 바뀐 항목은 강조해 보여 준다.
- **구현 메모:** 스토어에 "허용한 매니페스트 버전"(`Plugin.grantedVersion`)을 두고, `enabled`를 켜기 전에 비교한다. core 계약 변경이라 02-SSRD·ERD를 같은 PR에서 고친다.

### 2.3 휴대폰 앱 구조: 아래쪽 탭 세 개

| 탭 | 화면 | 내용 |
| --- | --- | --- |
| **보기** | S1 홈 | 카메라, 흰 전송 범위 틀(꼭짓점 끌기), 위쪽 전달 신호, 카메라 왼쪽 아래 보호 상태(앱에 반영된 사람 N명), 카메라 아래 "앱 결과" 칸(앱 카드), 오른쪽 위 "전달 멈춤" 버튼 |
| **앱** | S2 앱 목록 | 시드 앱 세 개를 한 장씩. 연결 전인 앱은 요청 조건을 칩(음식 앞에서만·긴 변·분당 장수·받는 곳)으로 보이고 **연결** 버튼(→ S4)을 둔다. 연결된 앱은 상태와 오늘 받은 사진 수를 보이고 누르면 S3. 시안은 시연 컷 1에 맞춰 연결 전 상태를 그렸다 |
| | S3 앱 상세 | 신원과 상태(연결됨 · 오늘 사진 N장), "이 앱이 받은 것"(최근 조각 3장, 누르면 S6, "기록에서 보기" → S5), **허용한 조건** 카드(2.2 허용 칸 + 허용한 조건 판 번호), 마지막으로 앱이 보낸 결과(앱 카드), 잠시 끄기, 연결 끊기 |
| | S4 연결 요청 | 2.2 화면. 꺼진 앱을 켤 때와 매니페스트가 바뀐 뒤 뜬다 |
| **기록** | S5 전체 기록 | 모든 앱의 전달·보내지 않음·연결 사건을 시간순으로. 앱별 걸러 보기. 위쪽 요약 세 칸: 앱에 보낸 사진 N장 · 가린 얼굴 N개 · 보내지 않음 N건. 원본 전송은 늘 0이라 요약에 넣지 않는다 |
| | S6 기록 상세 | 보낸 조각(가린 자리 표시), 받은 앱, 바이트와 원본 대비 면적, 흰 틀 크기, 가림(2a~2d를 쉬운 말로), 나가기 전 검사(출구 재검사)의 남은 얼굴 수, 앱 수신 확인, 증명 값(해시, 접어서), 그 조각에 앱이 보낸 결과(앱 카드) |

- 데스크톱(발표자) 화면은 지금 배치를 유지한다. 오른쪽 탭(로그·확인 화면·매니페스트·처리량)의 이름을 위 용어(기록·앱)에 맞춘다.
- `/hud`(글래스)와 `/outward`(바깥 표시)는 그대로 둔다. `/hud`에도 2.1 규칙을 적용한다. 앱 결과는 앱 이름이 붙은 줄로만 보인다.
- 지금 아래쪽 시트의 네 탭은 이렇게 옮긴다. 전달 일시 정지는 S1 버튼으로, 사용 기록은 S5로, 앱 관리는 S2·S3으로, 확인 화면은 S3의 "이 앱이 받은 것"으로 간다.

### 2.4 시연 영상 흐름(Claude Design용 스토리보드)

| 컷 | 화면 | 보여 줄 것 |
| --- | --- | --- |
| 1 | S2 → S4 | 칼로리 앱을 켜려 하자 연결 요청이 뜬다. 바꿀 수 없는 보장과 "요청 → 허용" 두 칸. 허용을 누른다 |
| 2 | S1 | 피자를 흰 틀 안에 둔다. "음식 앞" → 전달 신호 "framelet → 칼로리 앱 · 사진 1장" |
| 3 | S1 | 아래쪽 칼로리 앱 카드에 "피자 약 …kcal". 보호 상태와 분리돼 보인다 |
| 4 | S1 | 사람이 들어온다. 얼굴이 가려진 채 전달되고 "앱에 반영된 사람 0명"이 유지된다 |
| 5 | S5 → S6 | 기록 탭에서 방금 보낸 조각과 크기·가린 얼굴·받은 앱을 연다 |
| 6 | S3 | 칼로리 앱 상세: "이 앱이 받은 것은 이 사진 N장뿐", 규약 카드, 끄기 |
| 7 | S1 | 틀 꼭짓점을 줄이면 보내는 범위가 줄어든다(F24) |

### 2.5 시각 규칙 정리(ai-design-skills Part B에서 가져온 것)

지금 디자인 체계(`design-system.md`)는 유지하고, 아래만 맞춘다.

- **글꼴:** 앱은 Pretendard 하나만 쓴다(그 스킬이 금하는 Inter·Roboto 등은 쓰지 않음). 기울임과 900 굵기는 쓰지 않는다. 시안 캔버스는 Google Fonts만 불러올 수 있어 Geist와 Noto Sans KR로 그렸다.
  - 크기는 12·14·16·18·20·24·30·36px에서만 고른다. 본문은 16/24, 화면 제목은 24/32 semibold다.
  - HUD 카운터(40px 이상)는 기존 PRD 규칙을 따른다.
- **간격:** 0·2·4·8·12·16·24·32·40·48·64px만 쓴다. 기본 버튼 안쪽 여백은 8px×12px다.
- **모서리:** 8·12·16·24px·완전한 원만 쓴다. 겹친 모양은 안쪽 반지름 = 바깥 반지름 − 간격으로 맞춘다.
  - 앱 카드는 16px로 둔다.
  - 지금 카드(18px)와 틀(14px)은 각각 16px·12px로 맞춘다.
- **선과 배경:** 한쪽 면에만 선을 긋지 않는다. 배경 그라디언트는 쓰지 않는다.
  - 다크 배경은 `#131209`로 바꾼다. 지금 `#0c0b0a`는 그 스킬의 허용 목록 밖이고, 가장 가까운 따뜻한 검정이 `#131209`다.
- **아이콘:** Phosphor 한 벌만 쓴다. 자물쇠(보장), 화살표(전달 방향), 일시 정지, 탭 세 개(눈·격자·시계) 아이콘이 필요하다. 시안은 같은 모양을 선 SVG로 직접 그렸다.
- **움직임:** 곡선은 `cubic-bezier(0.22,1,0.36,1)`이다.
  - 색 바뀜은 300ms, 배치 바뀜은 500ms다. 200ms보다 짧게 하지 않는다.
  - `transform`·`opacity`만 움직인다. 움직임 줄이기 설정이면 투명도만 바꾼다.
  - 전달 신호(테두리 300ms 밝아짐)는 지금 규칙 그대로다.
- **상태:** 모든 누를 수 있는 요소에 눌림(`scale(0.98)`)과 보이는 초점 테두리를 둔다.
  - 기록이 없을 때는 빈 화면 문구를 둔다("아직 어떤 앱에도 보내지 않았습니다").
  - 불러오는 중에는 뼈대(skeleton)를 보여 준다.
  - `alert()`는 쓰지 않는다.
- **문구:** 문장형 대소문자를 쓰고, 느낌표 없이 차분하게 쓴다. 지어낸 숫자를 넣지 않는다. 시안의 숫자는 자리표시이거나 실제 실측값이다.

## 3. 고르지 않은 방법

| 방법 | 고르지 않은 이유 |
| --- | --- |
| 칼로리 결과를 보호 카운터 옆에 두고 색만 바꾸기 | 위치가 붙어 있으면 같은 주체로 읽힌다. 문제 1이 그대로 남는다 |
| 연결 요청 없이 켜기 스위치만 두기 | 무엇을 넘기는지 모른 채 켜게 된다. 규약이 코드에만 있고 사람에게는 보이지 않는다(문제 2) |
| 앱마다 자기 화면(iframe UI)을 그리게 하기 | 앱이 플랫폼 모양을 흉내 낼 수 있고, iframe에 화면 권한을 주면 격리 설계(F5)가 넓어진다. 이번에는 앱이 한 줄 텍스트만 돌려준다 |
| 탭 다섯 개(보기·앱·기록·설정·도움말) | 마감 앞에서 화면이 늘면 시연 흐름이 길어진다. 설정은 S3과 S1 버튼으로 충분하다 |

## 4. 남은 위험과 열린 질문

- **마감(오늘 12:00)까지 어디까지 구현하나.** 제안은 5절이다. 나머지는 시안과 시연 영상으로만 보여 준다.
- **용어:** 화면에서는 "앱", 개발 문서에서는 "플러그인"으로 쓴다(제안).
- **앱 추가:** 이번 데모의 앱은 시드 세 개(칼로리·변조·장면 기록)뿐이다. 앱 추가(스토어) 화면은 비목표(PRD)라 시안에도 넣지 않는다.
- **규약 다시 묻기:** 매니페스트 편집기(F11)로 값을 바꿀 때마다 연결 요청이 뜨면 발표 흐름이 끊길 수 있다. 발표자 화면에서 바꾼 값은 확인 한 번으로 넘기는 방법을 열어 둔다.

## 5. 구현 범위 제안과 확인 방법

**마감 전에 할 것(트랙 C 중심, core 한 곳)**
1. 앱 결과를 S1 아래쪽 "앱 카드"로 옮긴다. 아이콘·이름·꼬리표는 플랫폼이 그리고, 보호 카운터 옆의 결과 알약은 없앤다.
2. 전달 신호 문구를 "framelet → {앱 이름}" 형식으로 바꾼다.
3. 연결 요청 화면(S4)을 만든다. core에 `grantedVersion`을 두고 켜기 전에 확인한다.
4. 아래쪽 시트의 네 탭을 "보기·앱·기록" 구조로 바꾼다. S2·S3·S5·S6는 지금 있는 데이터(Counter.usage, usageSamples, logs, deliveries)만 쓴다.

**시안과 영상으로만 보여 줄 것:** 기록 걸러 보기, 연결 해제, 2.5의 색·모서리 수치 전부 반영

**확인 방법**
- `check:ui`에 시험을 둔다.
  - 앱 결과는 앱 카드 안에서만 그려진다.
  - 연결 요청에서 허용하기 전에는 `enabled`가 false다.
  - 매니페스트 버전이 오르면 다시 묻는다.
- 휴대폰(390px)에서 S1~S6을 열어 보고, 보호 카운터 주변에 앱 문구가 없는지 확인한다.

# famelet SRS: 소프트웨어 요구사항 명세

문서 03-SRS v1.6 · 2026-10-31 · **요구사항의 유일한 원본**. 근거: ① PRD(Oct 31, 2026) ② `00-추가결정사항.md`(이하 **D§n**. PRD의 미정 값보다 우선하고, PRD 본문과 충돌하면 PRD를 따른 뒤 §8에 적는다) ③ SRD v0.2 중 FR/NFR에 대응이 없던 것 ④ 팀원 SSRD 초안의 채택 항목(이전 판 PRD 기준 내용은 제외). 독립 리뷰어 2명(Opus·Sonnet)의 지적을 반영했다.

## 1. 소개

### 1.1 목적·독자·범위
PRD의 F1~F19와 G1~G5를 구현·시험 가능한 문장으로 바꾼다. 독자는 팀 A(런타임)·B(격리·플러그인)·C(UI)·D(PM·QA).
- **포함:** 배포 URL 하나로 도는 웹 런타임. 입력 → 0단계 판정 → 1단계 포착 → 2단계 가림·분기 → 중개기 → 격리 플러그인(iframe 안의 Worker) → 허용 목적지. 화면 4종(`/` 휴대폰·데스크톱, `/hud`, `/outward`)과 `/api/calorie`.
- **제외(PRD 비목표):** 실제 글래스 연결, iOS 네이티브, 원격 서비스·에이전트 연결(확장 설계로 발표에서만), 3단계 실구현(비활성 "미구현" 안내만), 동의 등록·인물 인식·인물 브리핑, 승인 카드, 플러그인 간 연동, 시선 추적(화면 문구도 "시선" 대신 "화면 중앙"), 스토어, 허용 목적지 안에서의 사용 통제, 권한을 철회했을 때 이미 받은 데이터의 회수. F18은 이번 제출에서 제외.

### 1.2 용어
| 용어 | 뜻 |
| --- | --- |
| 전달물 | 중개기가 플러그인에 실제로 보낸 Blob. ERD `Delivery` |
| 중개기 | 플러그인으로 가는 **유일한** 경로. 로그와 카운터는 여기서 계산한다 |
| 분기 2a~2d | 2a 그대로 전달 / 2b 얼굴만 가림 / 2c 머리 영역 넓게 가림 / 2d 보류(전달 안 함). 정확한 조건은 §4.2 |
| 보호 모드 / 비교 모드 | 기본 동작 / F17. 전송 범위 프레임(F24) 안의 원본이 가려지지 않은 채 칼로리 플러그인까지 넘어간다(프레임 밖과 서버로는 안 감, FR-047) |
| N / M / K | N = 화면 속 사람 수(0단계, 로컬 전용). M = 현재 앱에 반영된 사람 수. K = 바깥 표시의 "얼굴을 본 앱 수"(§4.3) |
| 전송 표시 | 화면에는 "원본 서버 전송 0건 / 가린 조각 API 전송 N건 / 기업 서버 재검사: 미구현"으로 나눠 보인다 |

### 1.3 ID·표기 규칙
- 공통 ID: G1 원본 비유출, G2 최소 전달, G3 격리와 출구 통제, G4 제3자 보호(불확실하면 차단), G5 입력 완전성. F1~F19는 PRD 번호.
- 이 문서: `FR`·`NFR`·`TC`·`EI`. 02-SSRD는 `SUB-A·B·C-##`·`IF-##`, 04-ERD는 엔티티 7개(Session, Plugin, SceneDecision, LogEntry, Delivery, Detection, Counter). 차단 이벤트는 `LogEntry(kind=violation)`.
- **요구값은 PRD·D 값만 쓴다.** 값이 없으면 **미정(열린 질문)**(PRD "남은 열린 질문"에 있는 것) 또는 **미정(PRD 미기재)**. PRD가 비운 규칙을 이 문서가 정한 것은 **결정 A-n**(팀 승인 완료, 2026-10-31). TC의 표본 크기·시간(10건, 1분 등)은 **시험 파라미터 (T)** 이며 요구값이 아니다.

## 2. 전체 설명

### 2.1 제품 관점
```
[입력] 웹캠·후면 카메라·녹화 mp4 → <video playsInline muted autoplay>
 → [0단계 판정기] 긴 변 640·5fps·EfficientDet-Lite0(로컬) → 장면, N
 → [1단계 포착] 원본 1장, 박스 +10% → [2단계] BlazeFace(256px·0.5) → 2a~2d → 긴 변 ≤ maxSide
 → [중개기] 단일 경로·로그·M/K·신호 → [플러그인] sandbox iframe 안 blob Worker, CSP connect-src = network
 → [허용 목적지] /api/calorie → 칼로리 AI   (3단계: 비활성 "미구현" 안내, 원본 서버 전송 0건)
```
웹 데모는 휴대폰(브라우저) 한 대가 카메라이자 처리 장치이므로 로그의 "처리 위치"로 이를 밝힌다. 사용자는 착용자, 찍힌 사람, 플러그인 개발자이고, 데모에서는 심사위원이 앞의 둘을 함께 맡는다.

### 2.2 운영 환경
- **클라이언트:** iPhone Safari, Android Chrome, 발표 노트북은 Chrome만(결정). `/hud` 확인도 Chrome(시뮬레이터가 Chrome 확장, D§1).
- **스택:** Vite + React 18 + TS strict, zustand, `@mediapipe/tasks-vision`, Vercel 함수(SDK 없이 `fetch`). UI 라이브러리와 테스트 프레임워크는 쓰지 않는다(D§4·§6).
- **배포·데이터:** Vercel HTTPS URL + QR, 설치 없음, 마일스톤마다 미리보기 배포. 영구 저장소 없이 탭 메모리(zustand)에만 둔다.
- **외부 서비스:** Anthropic API. `ANTHROPIC_API_KEY`, `CALORIE_MODEL`(기본 `claude-haiku-5-5`)(D§5).

### 2.4 보장의 한계 (발표에서 주장하는 범위)
- G4는 **감지된 얼굴**에만 적용된다. 사람 검출기와 얼굴 검출기가 모두 놓친 얼굴은 막지 못한다. 그래서 20회 실측치(NFR-014)로 말한다. 얼굴 검출(short-range 모델)은 가까운 얼굴을 정밀하게 가리고, 먼 사람은 사람 검출로 머리 영역을 넓게 가리도록(2c·2d) 나눈 설계다. 출구 재검사는 같은 모델로 다시 보는 것이라 가림 실수를 찾을 뿐, 처음 놓친 얼굴을 독립적으로 찾지는 못한다.
- 보장하지 않는 것: famelet을 거치지 않는 다른 앱, 호스트 코드(신뢰 대상이며 오픈 코드·네트워크 탭으로 확인), 허용 서버(`/api/calorie`·외부 AI)에서의 사용, 조각 안에 든 카드번호 같은 민감정보(인식이 아니라 최소화로 줄인다, D§2).

## 4. 상태 모델

### 4.1 장면 상태기계(전역)와 플러그인별 포착 게이트
- 상태는 `none` → 후보(L, t0) → 확정(L) 세 가지다. 0단계 틱(5fps)마다 라벨 L을 받는다.
- `none`에서 L ≠ none이면 후보(L, now). 후보(L)에서 같은 L이 now − t0 ≥ 1초 동안 이어지면 확정(L)(HUD 장면 표시).
- 후보나 확정 상태에서 다른 라벨 L′이 오면 L′ ≠ none일 때 후보(L′, now), 아니면 `none`. 확정(L)에서 같은 L이 오면 그대로 둔다.

**포착 게이트(플러그인 p마다, 틱마다 평가):** 장면 = 확정(L) ∧ L ∈ p의 선언 장면 ∧ p가 `ready` ∧ now ≥ p.cooldownUntil 이면 포착 1회 → 2단계 → 전달 또는 2d → `p.cooldownUntil = now + 60/maxPerMinute`.
- 결정 A-1: 쿨다운은 플러그인별이며 장면이 바뀌어도 초기화하지 않는다.
- 결정 A-2: 2d 보류도 쿨다운을 시작한다. 같은 사람에게 반복 시도하지 않기 위해서다.

### 4.2 2단계 분기 결정표
O = 사람 박스 ∩ 조각 > 조각 면적 5%. F = 얼굴 ≥ 0.5. P = (사람 박스 ∩ 조각) ≥ 조각 면적 50%. P가 참이면 O도 참이다.

| 규칙 | O | F | P | 분기 | 처리 | 신호 |
| --- | --- | --- | --- | --- | --- | --- |
| R1 | N | N | N | **2a** | 그대로 전달 | 소리·점멸·진동 |
| R2 | Y | Y | — | **2b** | 얼굴 +15%, 6×6 픽셀화 후 전달 | 소리·점멸·진동 |
| R3 | Y | N | N | **2c** | 위쪽 40% + 좌우 10% 픽셀화 후 전달 | 소리·점멸·진동 |
| R4 | Y | N | Y | **2d** | 전달 안 함 | 없음, 하단 "보류" |
| R5 | N | Y | N | **2b** | 검출된 얼굴은 모두 가린다 | 소리·점멸·진동 |

- 여러 사람(외부 검토 채택): F는 사람 박스마다 판단한다. 검출된 얼굴은 모두 가리고, 어느 사람에게도 대응되지 않은 얼굴도 가린다. 얼굴이 대응되지 않은 사람에게는 따로 R3·R4를 적용한다. 한 사람이라도 R4이거나, 얼굴-사람 대응이 불확실하거나, 사람 박스가 조각 경계에서 크게 잘렸으면 조각 전체를 2d로 보류한다.
- 2a·2b·2c 결과는 전달 전에 출구 재검사(FR-055)를 거친다. 얼굴이 남아 있으면 2d로 바뀐다.
- 프레임(F24, FR-060): 이 표의 "조각"은 프레임으로 자른 뒤의 조각이다. 사람 박스는 포착 프레임 전체에서 다시 찾은 것(FR-013)을 쓰고, O·P는 잘린 조각 기준으로 잰다. 그래서 프레임 경계에 걸린 사람도 잘린 조각과 겹치면 판단에 들어가고, "사람 박스가 조각 경계에서 크게 잘리면 보류" 규칙도 프레임 경계에 그대로 적용된다.
- 비교 모드에서는 이 표를 건너뛰되 쿨다운과 `maxPerMinute`은 그대로 적용한다(결정).

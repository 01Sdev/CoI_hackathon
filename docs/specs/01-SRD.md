# famelet SRD: 시스템 요구사항 문서

v0.3 · 2026-10-31 · 근거: PRD(2026-10-31판), `00-추가결정사항.md`. 요구사항 목록(FR·NFR), 보장 G1~G5, 처리 단계, 분기 2a~2d, 용어 정의는 SRS 1장을 따른다. 이 문서는 시스템이 놓이는 환경과 설계 근거만 다룬다.

## 1. 목적과 범위

famelet은 1인칭 카메라와 플러그인 앱 사이에 놓이는 웹 런타임이다. 앱에는 목적에 필요한 조각만 넘기고, 얼굴은 가리고, 넘긴 것은 증명 로그로 보여 준다. 해커톤 제출물은 심사위원이 배포 URL이나 QR로 바로 여는 웹 앱과 코드 저장소(레포)다. 레포에는 API 키 같은 비밀값을 넣지 않는다.

대상 기기는 1인칭 카메라를 단 글래스이고, 데모에서는 휴대폰이 그 역할을 대신한다. PRD는 바디카·펜던트·웹캠 항목에 취소선을 그었으므로 이들을 대상 기기로 주장하지 않는다. 노트북 웹캠은 개발과 발표용 입력일 뿐이다.

## 2. 시스템 컨텍스트

### 2.1 행위자

| 행위자 | 시스템과의 관계 | 주로 쓰는 화면 |
| --- | --- | --- |
| 착용자 | 카메라를 들고 플러그인을 쓴다. 넘어간 것을 로그와 HUD로 확인한다 | 휴대폰 모드, `/hud` |
| 찍힌 사람 | 카메라 앞에 있다. 자기 얼굴이 넘어갔는지 바깥 표시로 확인한다 | `/outward` |
| 플러그인 개발자 | 매니페스트를 쓰고 웹캠과 녹화 영상으로 시험한다 | 데스크톱 모드 |
| 심사위원 | 자기 폰으로 직접 실행해 착용자와 찍힌 사람 역할을 함께 체험한다 | 휴대폰 모드 |
| 발표자 | 데스크톱 모드로 3분 시나리오를 진행하고 비교 모드를 켠다 | 데스크톱 모드 |

### 2.2 외부 시스템

| 외부 시스템 | 역할 | 비고 |
| --- | --- | --- |
| Anthropic API | 칼로리 추정. `/api/calorie`가 가린 조각만 넘긴다 | 모델은 `CALORIE_MODEL`(기본 `claude-haiku-5-5`) |
| Vercel | 정적 파일, 모델과 WASM, `/api/calorie` 함수를 제공한다 | HTTPS |
| 브라우저 | 카메라, iframe sandbox, CSP, Worker를 강제한다 | 격리 보장의 집행자 |
| Ray-Ban Display 웹앱 시뮬레이터 | `/hud` 표시를 확인한다 | Chrome 확장. 600×600 화면과 D-pad를 재현한다 |

### 2.3 실제 글래스 구성과 웹 데모 구성

| 단계 | 실제 글래스 구성 | 웹 데모 구성 |
| --- | --- | --- |
| 0 훑어보기 | 글래스는 360×640, 2~7fps로 송출만 한다. 판정은 휴대폰이 한다 | 입력을 긴 변 640으로 비율을 유지해 줄이고 5fps로 EfficientDet-Lite0를 돌린다 |
| 1 포착 | 글래스가 단일 프레임을 캡처해 휴대폰으로 보낸다 | 같은 `<video>`에서 원본 해상도 프레임 1장을 쓴다 |
| 2 가림·분기 | 휴대폰 | 포착 프레임에서 대상과 사람을 다시 찾고, 줄이기 전의 조각에 BlazeFace를 돌려 사람마다 가린 뒤, 마지막에 출구 재검사를 한다 |
| 3 확장 | 기업 자체 서버(선택) | 구현하지 않는다. 비활성 "미구현" 안내와 "원본 서버 전송 0건" 표시만 둔다 |

웹 데모는 휴대폰 한 대가 카메라이자 처리 장치라서 단계가 물리적으로 나뉘지 않는다. 그래서 로그에 처리 위치를 표시하고, 실제 구성은 발표 그림으로 보여 준다.

Meta 글래스의 카메라 권한은 앱별로 처음 한 번만 묻고 Meta AI 앱에서 관리한다. Meta는 외부 앱으로 간 영상에 접근하지 않는다. 앱이 받은 프레임을 어디에 쓰는지 확인하는 주체가 없다는 뜻이고, famelet은 그 자리에 놓인다.

## 3. 운영 환경

| 항목 | 내용 |
| --- | --- |
| 대상 브라우저 | iPhone Safari, Android Chrome, 노트북 브라우저. 발표 노트북은 Chrome으로 정했다(`/hud` 시뮬레이터도 Chrome 확장). 그 밖의 버전은 미정이다 |
| 보안 컨텍스트 | HTTPS로 배포한다. 카메라 API(`getUserMedia`)는 HTTPS에서만 동작한다 |
| 라우트 | `/`(휴대폰·데스크톱 모드), `/hud`(글래스 모드), `/outward`(바깥 표시), `/api/calorie`(서버 함수) |
| 추론 | 모든 판정과 가림은 브라우저 안에서 한다. GPU가 실패하면 CPU로 돌리고, 둘 다 실패하면 전달을 멈춘다. 녹화 영상은 카메라 실패의 대안이다 |
| 데이터 | 영구 저장소가 없다. 프레임, 조각, 로그는 브라우저 메모리에만 있다. 서버는 받은 이미지를 저장하지 않는다 |
| 네트워크 | 행사장 와이파이를 쓰고 핫스팟을 예비로 둔다. 판정 중에는 네트워크를 쓰지 않는다 |
| 화면 동기화 | `/outward`는 같은 브라우저의 다른 창과 `BroadcastChannel`로 맞춘다. 다른 기기와는 동기화하지 않는다 |
| 설치 | 없다. URL이나 QR로 연다 |

## 4. 웹을 택한 근거

iOS 앱은 심사위원 폰에 배포하기가 사실상 불가능하다.

| 배포 경로 | 심사위원 폰에서 안 되는 이유 |
| --- | --- |
| iOS 무료 개발자 계정 | 내 기기에만 설치되고 7일이면 만료된다 |
| TestFlight | 베타 심사를 거쳐야 한다 |
| Ad-hoc 배포 | 기기마다 UDID를 받아 등록해야 한다 |
| 웹(선택) | URL이나 QR 하나로 설치 없이 열린다 |

iOS 네이티브 작업(Meta 개발자 센터 프로젝트, DAT 샘플 빌드)은 발표의 "다음 어댑터" 슬라이드 자료로만 쓴다.

## 5. 스택과 배포

| 항목 | 결정 |
| --- | --- |
| 스택 | Vite, React 18, TypeScript strict, zustand, `@mediapipe/tasks-vision`. UI 라이브러리와 테스트 프레임워크는 쓰지 않는다 |
| 모델과 WASM | CDN이 아니라 `/public`에 둔다. WASM은 `postinstall`에서 복사한다 |
| 라우팅 | `vercel.json`에서 `/hud` 경로를 재작성한다 |
| 서버 | `/api/calorie`는 Vercel 함수다. SDK 없이 `fetch`로 Anthropic API를 부른다 |
| 비밀값 | API 키(`ANTHROPIC_API_KEY`)는 서버 환경 변수에만 둔다. 빌드 결과물 `dist`에서 키 문자열이 나오지 않는지 grep으로 확인한다 |
| 배포 주기 | 마일스톤마다 Vercel 미리보기에 배포한다 |

## 6. 비목표

PRD의 비목표를 그대로 옮긴다.

- 실제 글래스 실시간 연결, 아이폰 중계, iOS 네이티브 앱 배포
- 3단계(기업 서버 재검사)의 실제 구현. 비활성 "미구현" 안내만 둔다
- 이미 넘어간 데이터의 회수. 권한 철회는 앞으로의 접근만 막는다
- 원격 서비스·에이전트 연결. 확장 설계로 발표에서만 다룬다
- 동의 등록과 인물 인식. 얼굴 특징값을 저장하면 제품이 생체정보를 다루게 된다
- 플러그인 간 연동, 이벤트 버스, "걷는 중" 같은 추가 장면
- 시선 추적. "시선" 대신 "화면 중앙"이라고 쓴다
- 플러그인 스토어, 승인 카드, 매니페스트 화면에서 새 플러그인 만들기
- 허용된 목적지에서 조각이 어떻게 쓰이는지의 통제. 범위는 "무엇을 받았는가"와 "어디로 나갈 수 있는가"까지다

## 7. 발표에서 주장하지 않을 것

| 주장하지 않을 것 | 이유 | 대신 말할 것 |
| --- | --- | --- |
| 배터리를 몇 % 아낀다 | 웹에서는 배터리를 잴 수 없다 | 처리량 패널의 모델 호출 횟수 |
| 촬영 LED가 켜진다 | 외부 앱이 스트리밍할 때 LED가 켜지는지 확인되지 않았다 | 말하지 않는다 |
| 몇 시간이고 켤 수 있다 | 시간 제한이 문서에 적혀 있지 않을 뿐이다. 배터리와 발열 한계는 모른다 | 공식 문서에 세션 시간 제한이 명시되지 않았다 |
| 카드번호를 인식해서 막는다 | famelet은 인식이 아니라 목적 영역만 보내는 방식으로 줄인다. 카드가 조각 안에 들어가면 같이 넘어간다 | 필요한 영역만 넘긴다 |

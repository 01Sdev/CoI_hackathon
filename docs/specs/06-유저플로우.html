famelet 유저플로우 02판

심사위원이 QR로 들어와 음식 한 장을 앱에 넘기고, 넘어간 것을 눈으로 확인하기까지의 흐름입니다. 팀이 기준 계약으로 정한 02-SSRD(2026-10-31 저녁판)와 PRD 반영본으로 다시 그렸습니다.

기준: 02-SSRD.md(인터페이스 계약), 03-SRS.md v1.5(요구사항), 04-ERD.md(데이터), PRD. 팀원의 "유저플로우 SSRD판"과 달라진 곳은 맨 아래 표에 있습니다.

  • 초록: 정상 전달, 얼굴이 넘어가지 않음
  • 주황: 비교 모드 전용
  • 빨강: 차단·폐기·정지
  • 회색: 전달 없음(보류·건너뜀)

3. 라이브 화면에서 갈라지는 조작

권한·입력·모드를 바꾸는 조작은 모두 4장의 전환 절차를 거칩니다. 나머지는 화면만 바뀝니다.

조작누가거치는 길화면에서 보이는 결과
로그 항목 열기착용자읽기만썸네일·바이트·면적 비율·분기, 상세에 해시와 수신 확인 상태. 확인 화면에서 "이 플러그인이 본 것은 이 사진 N장뿐" 초록
매니페스트 JSON 고치기개발자잘못된 JSON이면 기존 값 유지. 통과하면 전환 절차maxSide 256 → 64면 다음 전달부터 바이트가 줄어듦
network에서 주소 지우기발표자전환 절차(새 CSP)칼로리 호출 실패, 서버 도달 0건, 결과 줄에 "(고정표)" 빨강
변조 플러그인 켜기발표자전환 절차카메라·호스트 화면·외부 서버·외부 스크립트 네 가지 시도 실패. 로그는 "플러그인 내부 보고", 증거는 네트워크 탭의 서버 도달 0건, HUD 빨강 빨강
비교 모드 켜기발표자 화면에만전환 절차(connect-src 'none', apiBase: null)원본 전체 전달, 서버 요청 0건, 차단 기록 없음, 상단 주황 띠, 카운터 주황 주황
전달 일시 정지발표자 화면에만모든 플러그인의 전달 게이트만 닫음(iframe은 그대로)일시 정지 중 전달 0건, 다시 누르면 재개
비교 모드 끄기발표자 화면에만전환 절차(원래 network)보호 표시는 즉시 바뀌고, 카운터와 바깥 표시는 10초 안에 0. raw 썸네일 해제, 숫자 기록은 남김
입력을 녹화 영상으로 바꾸기발표자·심사위원전환 절차플러그인 코드 수정 없이 같은 흐름
새 세션 시작발표자전환 절차 + 카운터 초기화모든 숫자 0, 비교 모드 꺼짐. 이미 보낸 데이터를 회수하지는 않음

4. 전환 공통 절차

매니페스트 적용, 비교 모드 켜기·끄기, 입력 전환, 새 세션 시작이 모두 같은 순서를 따릅니다. 이전 권한으로 자동 복귀하는 길은 없습니다.

팀원 "유저플로우 SSRD판"과 달라진 곳

팀원 판은 팀원 SSRD v2 계약으로 그려졌습니다. 기준 계약을 02-SSRD로 정했으므로 아래가 바뀝니다.

항목팀원 판이번 판(02-SSRD)
첫 메시지ready 뒤 bootinit(매니페스트, apiBase, 코드) → ready → delivery
칼로리 라벨label 쿼리 문자열x-label 헤더, 값은 물체 라벨(objectLabel)
음식 우선 영역프레임 중앙 50%화면 가운데 60%
빈도 제한최근 60초 전달 수고정 간격 쿨다운 60 / maxPerMinute초, 보류도 쿨다운 시작
2단계 분기조각에서 얼굴을 찾으면 2b사람 박스마다 얼굴 대응을 따로 판단, 한 사람이라도 보류 조건이면 전체 보류
출구 검사보이는 얼굴이 있으면 폐기같음. 검사가 실패해도 0으로 세지 않고 보류
해시로그에 먼저 남기고 보냄기대 해시는 호스트만 보관하고 메시지에 싣지 않음
보낸 것으로 세는 기준로그에 남으면 전달dispatched만 전달. 거부되면 failed
기록 구조DeliveryLog, PluginReportLog, RuntimeStateLogEntry, Delivery, Counter(화면 로그와 별개인 숫자 기록)
비교 모드 켤 때칼로리 호출이 막혀 차단 기록과 섞임apiBase: null이라 요청을 아예 하지 않음
비교 모드 끈 직후즉시 0보호 표시는 즉시, 카운터는 10초 안에 0
바깥 표시로 보내는 값RuntimeState숫자와 불리언만(OutwardMessage)
시작 버튼뺐음유지(오디오 잠금 해제, 카메라 권한 요청)
인식 엔진 실패그림에 없음GPU → CPU, 둘 다 실패하면 전달 정지
전환 실패그림에 없음3초 안에 ready가 없으면 플러그인 정지

팀원 판이 "팀이 정해야 할 것"으로 남긴 다섯 가지 중 같은 장면 재전달, 대상 재검출 실패, 비교 모드 직후 카운터, 비교 모드 켤 때의 처리는 위 표대로 정해졌습니다. 사람 장면의 "전달 0건"은 로그에 남기기로 정했습니다(결정판 N5).

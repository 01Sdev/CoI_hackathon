# framelet

framelet은 1인칭 카메라와 그 위에서 도는 앱(플러그인) 사이에 두는 웹 런타임이다. 앱은 원본 프레임 대신 목적에 필요한 조각만 받고, 찍힌 사람의 얼굴은 가린 뒤에만 넘어간다. 착용자는 넘어간 조각을 로그로 확인하고, 이번 데모는 그 경계를 브라우저 안에서 실행한다.

데모: https://framelet-demo.vercel.app

발표자 화면은 같은 주소에 `?tools`를 붙이고 폭을 768px 이상으로 둔 경우다. 그 화면에만 비교 모드 스위치, 새 세션, 바깥 표시, 매니페스트 편집기가 있다. 로그와 전달 일시 정지는 그 화면의 오른쪽 패널·발표자 막대에 있고, 폭이 768px 미만인 `/?tools`에서는 아래 시트에 있다. 쿼리 없는 `/`는 글래스 홈만 그려 이 도구를 보여 주지 않는다.

## 글래스 홈

`/`는 카메라 권한, 앱 홈, framelet 런처, 고른 앱 순서로 간다. 홈은 4/5/4칸이고 정가운데가 framelet이다. 런처 버튼은 칼로리, 코디 스캔, 변조 시험이다. 그 옆의 기성 앱 아이콘과 "추가..."는 화면을 바꾸지 않는다. 앱을 고르면 그 플러그인만 켜지고, 홈이나 런처로 돌아오면 꺼진다.

## 칼로리 (보호 모드)

칼로리 앱은 음식 조각을 받아 칼로리를 한 줄로 낸다. 순서는 기기 안 모델, `/api/calorie`, 고정표다. 기기 안 모델은 전달을 받은 뒤 8초를 넘기거나 쓸 수 있는 결과가 없으면 넘어간다. `/api/calorie`도 실패하거나 3초 안에 본문이 없으면 음식 라벨의 고정표를 쓴다. 비교 모드에서는 통신이 막혀 고정표만 쓴다.

칼로리 플러그인이 켜질 때 브라우저가 모델과 ORT wasm을 받는다. 모델은 `public/models/calorie-lens/`의 두 조각으로 약 94MB이고, `npm ci`가 `public/ort/`에 복사하는 ORT wasm은 14MB다. 합계는 약 108MB다. 글래스 홈에서는 칼로리 앱을 처음 열 때 받는다. `/?tools`에서는 칼로리 플러그인이 처음부터 켜져 있어 세션을 시작할 때 같은 파일을 받는다. 물체·얼굴 검출 모델은 이 합계에 들어 있지 않고, 카메라 파이프라인이 따로 불러온다.

## 코디 스캔

코디 스캔이 켜져 있을 때, 시야 가운데 사람을 3초 보면 그 사람 위에 "마스크 해제"가 뜬다. 누르면 그 사람만 앱으로 가고 얼굴은 계속 가린다. 동의는 사람마다 따로이며, 최대 60초이고 그 사람이 2초 넘게 안 보이면 끝난다. 질문은 가린 조각과 함께 `/api/outfit`으로 가고, 서버는 Gemini로 답한다. 답이 없으면 대체 문장을 보여 준다.

동의가 한 명이라도 살아 있고 코디 스캔이 켜져 있으면, 질문을 하기 전에 ElevenLabs Scribe 연결이 열린다. 말소리는 그 서비스로 나간다. 토큰이 없거나 연결이 실패하면 브라우저 음성 인식으로, 그것도 없으면 입력창으로 바뀐다.

## 얼굴 가림과 비교 모드

보호 모드에서는 조각을 보내기 전에 얼굴을 픽셀로 가린다. 가린 뒤 검사에서 얼굴이 남으면 그 조각은 보내지 않는다. 흰 틀 밖 픽셀은 어떤 앱에도 보내지 않는다.

비교 모드는 발표자 화면의 스위치로만 켠다. 켜면 흰 틀 안을 가리지 않은 채로 칼로리 플러그인에만 넘기고, 그 플러그인의 네트워크는 막는다. 틀 밖은 이때도 나가지 않는다. 스위치 상태는 메모리에만 있어 새로고침하면 꺼진다.

## `/hud`와 `/outward`

`/hud`는 600×600 글래스 HUD다. 입력은 녹화 영상이고, 영상 자체는 화면에 보이지 않는다. `/outward`는 같은 브라우저의 다른 창에 "지금 당신의 얼굴을 본 앱" 수를 보여 준다. 다른 기기의 브라우저와는 맞지 않는다. 발표자 막대의 "바깥 표시 열기"가 이 경로를 연다.

## 로컬에서 실행

```bash
npm ci
npm run dev
npm run build
npm run check:core
npm run check:plugins
npm run check:api
npm run check:ui
npm run check:runtime
npm run check:boot
```

`npm ci`는 MediaPipe WASM을 `public/wasm/`에, ORT wasm을 `public/ort/`에 복사한다. 서버 키는 `.env.example`을 `.env.local`로 복사한 뒤 이름 세 개만 채운다. 값은 저장소에 넣지 않는다.

- `ANTHROPIC_API_KEY` — `/api/calorie`
- `GEMINI_API_KEY` — `/api/outfit`
- `ELEVENLABS_API_KEY` — 받아쓰기 일회용 토큰(`/api/scribe-token`)

키가 없으면 `/api/calorie`는 실패하고 칼로리 결과는 고정표로 간다. 코디 스캔은 대체 문장을 내고, 받아쓰기 토큰은 실패해 브라우저 음성 인식이나 입력창으로 넘어간다. 기기 안 칼로리 모델은 키 없이 동작한다.

## 디렉터리

| 경로 | 내용 |
| --- | --- |
| `src/input/`, `src/vision/`, `src/broker/` | 입력, 판정·포착·가림, 중개 |
| `src/plugins/`, `api/` | 플러그인 격리, 칼로리·코디 스캔·변조, `/api/calorie`·`/api/outfit`·`/api/scribe-token` |
| `src/ui/`, `src/proof/`, `src/App.tsx` | 글래스 홈, HUD, 로그, 경로 |
| `src/core/` | 타입, 스토어, 매니페스트, 칼로리 고정표 |
| `public/models/` | 검출 모델과 calorie-lens |
| `docs/specs/` | 제품·인터페이스 명세 |
| `scripts/` | `check:*`와 wasm 복사 |

## 한계

- 스마트 글래스 기기가 아니다. 휴대폰·데스크톱 브라우저가 그 시야를 흉내 낸다.
- 글래스 홈에서 카메라를 거부하거나 카메라와 대체 영상을 모두 열지 못하면, 녹화 영상으로 이어 가지 않고 안내만 보여 준다. `/hud`가 쓰는 녹화 영상 파일은 이 저장소에 없다.
- `/outward`는 같은 브라우저의 창끼리만 `BroadcastChannel`로 맞춘다.
- 비교 모드는 발표용 예외다. 가리지 않은 틀 안이 칼로리 플러그인으로는 가지만, 그 사이 통신은 막혀 있다.
- 기업 서버 재검사는 처리량 패널에 "미구현"으로만 있고 요청을 보내지 않는다. `/?tools` 데스크톱에서만 그 패널이 보인다.
- 전달 일시 정지와 새 세션은 이후 전달을 멈추고, 새 세션은 화면의 로그를 비운다. 이미 서버로 간 요청을 취소하지는 않는다.
- 코디 스캔 동의가 한 건 생기는 순간, 질문을 하기 전에 마이크가 ElevenLabs에 연결된다.

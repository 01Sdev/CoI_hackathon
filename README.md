# framelet

> 카메라 앱이 무엇을 가져갔는지, 눈으로 확인할 수 있게 한다.

**데모:** https://framelet-demo.vercel.app (설치 없음. 휴대폰은 후면 카메라, 노트북은 웹캠을 씁니다)

INTHON 해커톤(마감 2026-11-01 12:00 KST) 제출 레포입니다. 플랫폼 이름은 framelet입니다(2026-10-31 확정. 2026-11-01까지 famelet으로 잘못 적었고, 그 전 가칭은 LensGate).

## framelet이 하는 일

framelet은 1인칭 카메라와 그 위에서 도는 앱(플러그인) 사이에 들어가는 웹 런타임입니다.
- 앱은 원본 프레임 대신 목적에 필요한 조각 한 장만 받습니다.
- 찍힌 사람의 얼굴은 가려진 채로만 넘어가고, 위치가 불확실하면 아예 넘어가지 않습니다.
- 착용자는 무엇이 어느 앱으로 넘어갔는지 증명 로그로 직접 확인합니다.

이 데모의 앱은 피자 사진 한 장으로 칼로리를 알려 주는 "칼로리 플러그인"입니다.

### 다섯 가지 보장
1. **원본 비유출:** 원본 프레임과 가리기 전 조각은 브라우저 밖으로 나가지 않습니다. 판정과 가림은 모두 이 기기 안의 모델로 합니다.
2. **최소 전달:** 앱은 매니페스트가 선언한 장면에서, 선언한 영역만, 선언한 해상도·빈도 이하로 받습니다. 흰색 뷰파인더 틀(전송 범위 프레임) 밖의 픽셀은 어떤 앱에도 가지 않습니다.
3. **격리와 출구 통제:** 앱 코드는 `sandbox="allow-scripts"` iframe 안의 Web Worker에서 돕니다. 카메라와 호스트 화면에 닿지 못하고, 네트워크는 매니페스트가 요청하고 호스트가 허용한 주소로만 나갑니다.
4. **제3자 보호:** 사람과 겹친 조각은 얼굴을 가립니다. 얼굴 위치가 불확실하면 머리 영역을 넓게 가리거나 보내지 않습니다. 보내기 직전에 얼굴을 한 번 더 셉니다(출구 재검사).
5. **입력 완전성:** 앱에 전달한 카메라 데이터는 증명 로그에 있는 것이 전부입니다. 전달 경로가 중개기 하나뿐이기 때문입니다.

## 3분 안에 해 보기
1. 휴대폰이나 노트북에서 데모 주소를 열고 **시작하기**를 누릅니다. 카메라 권한을 한 번 묻습니다.
2. 피자(사진이나 화면 속 피자도 됩니다)를 화면 가운데 **흰 틀 안**에 1초쯤 둡니다. "음식 앞"이 뜨고, 조각 한 장이 칼로리 앱으로 넘어가며 테두리가 깜빡입니다. 결과 줄에 "피자 약 …kcal"이 나옵니다.
3. 사람이 함께 찍히면 그 얼굴은 가려진 채로 넘어갑니다. HUD의 "앱에 반영된 사람"은 0명으로 남습니다.
4. **로그** 탭에서 실제로 보낸 조각의 썸네일, 바이트, 원본 대비 면적, 분기(2a~2d), 프레임 크기를 봅니다. **확인 화면**은 "이 앱이 본 것은 이 사진 N장뿐"을 보여 줍니다.
5. 틀의 꼭짓점을 끌면 보내는 범위가 바뀌고, 다음 전달부터 로그에 반영됩니다.
6. `/hud`(글래스 화면)와 `/outward`(찍히는 사람을 향한 화면) 경로도 직접 열 수 있습니다.

"녹화 영상으로 보기"에 쓸 시연 영상(`public/demo/pizza-alone.mp4`)은 아직 준비 중입니다.

## 어떻게 동작하나
- **0단계 훑어보기:** 영상을 줄여 5fps로 물체를 판정합니다(MediaPipe EfficientDet-Lite0, 이 기기 안). 화면 가운데의 피자가 1초 유지되면 "음식 앞"으로 확정합니다.
- **1단계 포착:** 원본 해상도 프레임 한 장에서 대상 박스를 넓히고, 전송 범위 프레임과 겹치는 부분만 자릅니다.
- **2단계 가림·분기:** 자른 조각에서 얼굴(BlazeFace)과 사람을 보고 2a(그대로)·2b(얼굴 가림)·2c(머리 영역 가림)·2d(보류)로 나눕니다. 줄여서 JPEG로 만든 뒤 출구 재검사를 합니다.
- **중개기 → 플러그인:** 통과한 조각만 sandbox iframe의 Worker로 갑니다. 칼로리 플러그인은 그 조각을 `/api/calorie`(Vercel 함수, Claude Haiku)로 보내고, 실패하면 고정표 값을 씁니다.
- **증명:** 보낸 조각과 바이트·해시·분기를 로그에 남기고, 서버는 받은 바이트와 해시를 응답 헤더(`X-Framelet-Body-Bytes`·`X-Framelet-Body-SHA256`)로 돌려줍니다.
- **호스트 외부 요청 차단:** 호스트 창의 `fetch`·XHR·`sendBeacon`은 같은 origin으로만 갑니다(MediaPipe의 로그 요청도 막힘).

자세한 계약은 `docs/specs/`에 있습니다.
- `PRD.md`: 제품 범위와 데모 시나리오
- `02-SSRD.md`: 메시지·매니페스트·`/api/calorie`·전환 절차
- `03-SRS.md`: 요구사항과 시험
- `04-ERD.md`: 메모리 데이터 모델
- `05-코드-전-결정사항.md`: 결정과 실측 결과

## 로컬에서 돌리기
```bash
npm ci
```
`npm ci`가 끝나면 `postinstall`이 MediaPipe WASM을 `public/wasm/`으로 복사합니다. 모델 파일은 `public/models/`에 들어 있습니다.

```bash
npm run dev
```
칼로리 AI까지 쓰려면 `.env.local`에 `ANTHROPIC_API_KEY`를 넣습니다. 없으면 칼로리 결과는 고정표 값으로 나옵니다. 키는 서버 쪽에서만 읽고 화면 번들에 들어가지 않습니다.

검사(테스트 프레임워크 없이 assertion 스크립트로 확인합니다):
```bash
npm run typecheck && npm run check:core && npm run check:plugins && npm run check:api && npm run check:ui && npm run check:runtime && npm run check:boot && npm run build
```

## 레포 구조
| 경로 | 내용 |
| --- | --- |
| `src/input/`, `src/vision/`, `src/broker/` | 입력, 0~2단계 판정·포착·가림, 중개기(원본 픽셀은 여기서만 다룸) |
| `src/plugins/`, `api/` | 플러그인 격리(iframe·Worker·CSP), SDK, 칼로리·변조·hello 플러그인, `/api/calorie` |
| `src/ui/`, `src/proof/`, `src/App.tsx` | HUD, 로그, 확인 화면, 매니페스트 편집기, 발표자·착용자 제어, 바깥 표시 |
| `src/core/` | 공용 타입, 매니페스트 검증, zustand 스토어, 프레임 좌표 함수 |
| `src/boot/`, `src/main.tsx` | 시작 배선과 호스트 외부 요청 가드 |
| `public/models/` | MediaPipe 모델 3개(출처·라이선스는 `THIRD_PARTY_NOTICES.md`) |

## 한계(발표에서 주장하는 범위)
- 브라우저가 강제하는 경계는 호스트와 플러그인 사이 하나입니다. 호스트 안의 코드 경계(원본 픽셀 접근 위치)는 코드 규칙으로 지킵니다.
- 출구 재검사는 같은 얼굴 모델로 다시 보는 것이라, 처음에 놓친 얼굴을 독립적으로 찾는 장치는 아닙니다.
- 이미 넘어간 데이터는 회수하지 못합니다. 끄기와 일시 정지는 앞으로의 전달만 막습니다.
- 실기기에서 아직 확인하지 않은 항목이 있습니다. 상태는 `docs/specs/05-코드-전-결정사항.md` V 표에 있습니다.
